# 固定128题的后续迁移准备

`transfer128_prepare_v1.py prepare`只重放已冻结的训练侧抽样与联合选位，不读取官方test、不加载模型、不换题。实际得到128个根题、412个联合位置/类型请求：270个请求可复用原general7b的完全相同提示与原始输出，另外142个尚未生成。两个联合位置最多四个非空解释；有些根题缺少位置，照样保留名单和失败预算，不补抽。

270个复用记录绑定原生成记录SHA、提示/输出SHA以及原v3自动判定SHA。原先被拒绝的输出继续拒绝，不重新生成。先前NLL请求的文本只有当它恰好也是当前联合位置、且上下文和提示完全相同时才能复用；这不会把NLL独有位置加入G4。所有新请求仍使用既定general7b提示和一次尝试。原7179训练根题、原17932输出、两份质量128名单及迁移128名单均保持不变。

输出位于`output/tgrd_v1/transfer128/preparation_v1/`，包括全部请求、待生成请求、逐条精确复用注册表、根题准备表及输入哈希清单。根题表的`awaiting_actual_template_review`表示尚无经过实际检查的6Vsel+6Vaudit变式，不能当作已完成审核或终止失败。准备文件不授予试学、正式训练或公开评测权限。142条新解释仍未生成，也未被自动或语义接受；其后续质量证据必须单独保存，不能伪造原v3已覆盖这些新输出。

`fixed_trial_engine_v1.py`为固定配置的128题确认试学增加独立状态机，保留历史四阈值开发引擎。调用者必须先验证真实general34全网格得出的配置、输入哈希及精确合格探针。每个分支从相同S0、空优化器和seed701重新开始，只用原题/原CoT或插入解释后的原题训练，更新次数采用冻结的1/3/5之一。六条Vsel的真实解题准确率与答案NLL按既定双门槛选择，在读取Vaudit预测前写入不可覆盖的单一决定；随后只审核e0和获选分支。Vaudit负收益不改选。该状态机不再额外跑其他阈值的Vaudit；每根题最多6条未训练Vsel、30条分支Vsel和12条Vaudit，共48次生成。

13项新增CPU检查覆盖名单/位置/提示/输出/历史拒绝隔离、单阈值选择、审核不改选、断点和篡改阻断，并用真实微型MLX CPU模型验证中断后新建模型加载已提交适配器，恢复时不重复训练。总计177项CPU集成检查通过。这些是工程检查，不是数学迁移效果。

`preflight_fixed_trial_driver_v1.py`是独立实际学生GPU工程预检，使用合成题面、每分支一次真实更新、32token工程生成，验证冷加载/恢复/缓存重放与单一决定先于审核。它排在G1–G3完整训练后，当前尚未执行，不能称实际GPU通过。科学试学仍须1024token和真实完整探针。

后续仍需142条解释实际生成及适当质量证据、可靠变式及逐题模板实际审查、真实全网格配置冻结、128题试学/审核汇总，以及G4/G5正式材料、训练和评测适配。若开发全非正，保留无支持结果，不自动启动扩大试学。准备与工程通过不证明方法有效。
