# 短训练驱动与断点恢复

实际试训和工程预检调用同一个 `trial_engine.run_root`。每题先冻结来源、解释池、Vsel/Vaudit元数据、种子、更新数及S0适配器哈希。不同解释和普通CoT的e0分支各自从S0及新优化器开始，执行相同次数的原题completion训练。变式答案不进入梯度。

每个分支保存两级状态：

1. `adapter.safetensors` 与 `trained.json`：记录已完成训练、权重哈希及更新日志，在长时间探针生成之前提交。
2. `Vsel.jsonl` 与 `summary.json`：探针逐条落盘；完成六题后提交分支指标。

中断后的再次执行会核对候选及适配器签名、恢复已训练权重并继续缺失探针，不重复已提交训练。已存在但无对应训练提交的权重文件作为 `uncommitted_adapter_*.safetensors` 保留后重做该分支，不直接覆盖。来源、解释、探针、配置或权重变动时拒绝混用旧输出。

所有解释分支的Vsel完成后，才将四个预设阈值的选择写入不可改写的 `decisions_before_audit.json`。随后仅恢复e0和已选中的适配器，独立求解Vaudit，记录负增益也不改选。结束后将当前学习器重置回S0；正式训练仍需重新建立学习器。

新增5项CPU状态机检查使用明确的虚拟学习器，不是模型学习效果：

- 两分支训练预算相等、初始权重相同、优化器对象分离。
- 人为令Vsel胜者在Vaudit更差，验证选择不会因审计结果改变。
- 训练提交后故意中断，恢复时验证没有重复训练。
- 完成后重复执行，验证输出及权重文件均不变。
- 检测权重/材料变更，保留未提交适配器，并覆盖仅e0回退。

与原检查合计30项CPU测试通过。此结果不替代真实GPU驱动预检。

`preflight_trial_driver.py` 已实现并排队，需在当前7473教师生成释放共享GPU锁后运行。它只使用助手编写的一道合成加法题、两个真实LoRA训练分支和两组各六道合成探针；在第二分支训练提交后故意中断，重新加载一个真实学生模型，验证恢复、选择/审计顺序和缓存重放。成功前不会写出 `preflight/trial_driver_gpu_v1.json` 的passed门槛；校准试训入口还核验此门槛的源码和输入签名。

工程探针最多生成32 tokens以控制检查成本，可能截断答案，不用于声称模型准确率或方法有效性。校准及正式评测仍为原定最多1024 tokens；只允许相同门槛下的可比科学实验。合成工程题不含官方test题目。

真实GPU预检通过且共享池完成全文数学/泄漏审核后，34题开发队列包含updates=1/3/5、trial seed=701及复测1701，逐次输出四个阈值0/.01/.03/.10。每个种子12个配置，后一个种子用于重复检查，均不是本轮正式七组的42（后续可选7、17）。Vaudit在此为超参数开发数据，不能声称独立确认结果。
