# 完整句/段删除对照：独立开发诊断

现有 v2 定位以 attention 选择前文单位，但删除的是其中的内容 token；随机对照也可能是散落 token。它控制删除 token 数和前文来源，不能据此声称证明了语义依赖。本次保留 v2 源码、候选位置和已有输出，另建 `whole_span_masking.py` 与 `whole_span_probe.py`。

新诊断将题面按标点句界、前文解答按空行段界切成完整片段。删除包含片段内标点及排版的全部连续 token；若 tokenizer 的一个 token 横跨字符边界，则整片段不纳入，不截断 token。完整句和空行段是句法启发式，可能仍含标题、指代或不完整语义，不能等同人工认证的语义单位。

对 attention 密度最高的片段，要求三个不同且不重叠的对照，均为相同来源、相同片段类型、完全相同 token 数的完整片段。对照不包含该最高片段。只使用当前步骤之前的上下文，所有前向止于当前步骤的最后一个计分 token；删除后重映射并验证原始目标 token 不变。只有三份对照齐备，才计算“最高片段删除增量减对照平均增量”。不够时保留缺失和单独删除增量，不拿散落 token 补足，也不改变原选择器。

## 本轮真实数据上的 CPU 覆盖结果

对已审核的 34 个校准根题、91 个候选步骤做真实学生 tokenizer 检查。**0 / 91 步骤存在任何一个可配齐三个完全等长完整片段对照的前文片段**；68 个片段因 token 边界原因未纳入。前者已经是 attention 选胜者之前的存在性上界，因此无需加载模型就能确认本轮不可能形成合格对照比较。

该负结果保留在 `output/tgrd_v1/preflight/cal40_reviewed34_v2_whole_span_cpu_v1.json`。本轮不为这个零覆盖方案消耗 GPU，不放宽长度条件来制造通过，也不据此修改 v2 定位或宣称方法失败。它说明“每步三个同类型、同长度完整段落对照”在这些短解答中覆盖不足；语义对照仍需继续设计和独立审核。数据驱动设计变更须另开版本、披露放宽条件，并在方法/阈值冻结前完成。

长度与类型匹配也没有消除片段离当前步骤的距离、语义相关性及删除引起的位置变化。即使未来有完整片段比较，也仍是诊断而非因果证明或学习增益证据。

## 工程验证

六项 CPU 检查使用独立构造的上下文效应，验证完整边界/标点保留、严格匹配、删除后的原始目标及前缀边界、带符号差值、缺失对照不回退到 token 碎片，以及 attention 观测改变 NLL 时拒绝。真实模型尚未运行此诊断；没有读取公开 test，也没有生成解释或正式训练。
