# 当前协议的分阶段公开评测

新入口是 `evaluate_selector_stage.py`，产物命名空间为
`output/tgrd_v1/evaluation/selector_first_transfer128_seed42_v1/<M1|NLL|M3>/seed42/`。
旧 `evaluate.py`、`evaluation_inputs.py` 及已通过真实 GPU 的适配器加载证据保留。
新入口复用已验证的 `mlx_lm.load(..., adapter_path=目录)` API。此次 CPU 验证不表示新入口已经实际完成 GPU 评测。

## 训练产物检查

公开测试前重建原来的前三组训练门槛，继续使用 7179 条统一自动准入和已完成的固定 128 条质量抽检。
不恢复 7473 条全文语义审核前置条件。统一自动准入不等于语义正确。
前三组必须全部完成；后两组材料完成不是前三组评测产物的要求。
逐组验证共同根题顺序、材料 SHA、训练调度 SHA、共同 S0/LoRA、seed42、4 epoch、更新数、4N 根题曝光、最后检查点适配器和优化器提交。
兼容实际训练引擎的 `inputs.primary_checkpoint=last_epoch4_not_selected_on_test` 与
`metadata.primary_checkpoint=last_epoch4`，不能将旧门槛改名充当新实验。

## 迁移抽样

`transfer128_sampling.py prepare` 在完整独立 NLL 完成后冻结训练侧抽样规则、标签、排除名单和预计算抽样结果。
`freeze-roster` 等联合诊断完整结束并验证后才冻结最终名单。
分层使用问题文本的固定优先级词汇规则与最大步骤 NLL 难度三分位；无步骤者保留单独层。
题型标签只是粗粒度词汇启发式，不宣称人工语义标注。
按层大小比例用最大余数法分配 128 个名额，再用 seed42 确定性抽取。
排除已有历史开发/训练曝光清单、cal40 和真实工程预检根题；不能按 joint 控制是否有效、解释是否合格、变式是否成功或试学收益过滤。
规则、标签与名单均保存输入 SHA；任何失败不换题。该实现细节是对用户已确认分层方案的工程落实。
名单与质量抽检的 128 题名单用途不同。

## 开启公开 test 的额外条件

首次读取公开 test 前还必须完成真正的迁移预冻结，不能仅凭 CPU 通过或手写“已通过”字段。

1. 完成已声明的 general7b 开发网格；冻结入口从原始预测和签名重建全 24 个种子/配置单元的既定汇总。
2. 提交可重现的正式迁移 128 名单、完整规则和具体披露记录。
3. `freeze-pretest --roster ... --rules ... --disclosures ...` 写入独立迁移预冻记录。
   `rules` 必须逐字段等于 `evaluation_selector_inputs.TRANSFER_RULES`；配置从实际开发汇总取得。
   披露必须包含历史公开测试曝光、开发题回收训练、自动教师质量噪声、单 seed 和解释长度差异的具体描述。
4. `freeze-gate` 检查实际前三组训练产物和上述证据后才能建立当前阶段公开评测门槛。
5. `run --condition M1 --seed 42` 等执行全 1319 题、greedy、最多 1024 新 token，使用第 4 epoch 最终权重。

若完整开发汇总全部非正，预冻记录只能写“无支持、不自动扩量、后续范围待处理”，不能伪造迁移配置、把后两组算作已完成或反复搜索正结果。前三组结果仍须与该限制一起报告。
此模块没有制造实际开发结果、迁移名单或训练产物来解除门槛；当前相应证据尚未齐备，公开评测继续关闭。

预测逐条持久化，恢复时核对题目、顺序、gold、模型签名、prompt、原始输出与重新计算的两种评分。
完整缓存可修复最后一条预测写入后中断的汇总，无需重载模型。
部分预测不报告为完整 test。没有本轮公开结果驱动的调参、检查点选择或更换迁移题目。
前三组评测入口不代表五组实验全部实现或完成；G4/G5 的正式材料、训练与公开评测适配仍需随后实现。
