# P60/H200 预留题的历史暴露核查 v1

本轮仅做 CPU 数据核查，不读取公开 test、不运行模型，不授予确认或正式训练门槛。输入为已冻结的 7473 train 根题、原历史暴露清单及已有 P60/H200 候选，未重新抽题。

脚本 `confirmation_exposure_audit.py` 先冻结词面重复规则，再检查：

- 历史清单中 9 个源文件的哈希保持不变；已知历史暴露共 750 个 train 根题。
- P60 的 60 题和 H200 的 200 题与已知历史 ID、彼此均无重复；候选每个完整记录必须与正式 train 源记录相等，不能仅靠 ID 对上而替换题干或 gold。
- 在候选对历史、候选内部、P60 对 H200 三类配对中，以五词 shingle 的 Jaccard ≥0.75，以及数字抽象后四词 shingle 的 Jaccard ≥0.75 标记近重复。使用整数比较，不因浮点四舍五入跨阈值。题干先 NFKC、casefold 和分词；数字抽象保留千分位及小数为一个单位。短题按整个非空 token 串处理。
- 当前已签名教师输出仅截取完整换行记录；验证每条签名、题干及输出哈希和冻结顺序，记录有多少候选已经生成。生成本身与学生训练、选择器调参分别披露。
- 单独记录本阶段已有全文审核是否涉及候选。全文准备审核不是学生性能反馈，但这些题不能被描述成“本项目完全无人看过”。

实际首个报告为 `output/tgrd_v1/confirmation_exposure_v1/audit.json`。260 个候选的词面规则触发配对数为 **0**；这只排除了上述阈值内的词面重复，不是语义题族隔离、外部历史暴露或预训练未见的证明。已有 **11** 个候选接受过本阶段全文审核，其确切 ID 保存在报告中。报告不因其正确性、难度或审核结论自动换题，也没有模型性能输入。

独立 CPU 测试 4 项通过：数字正规化；历史及候选内部/跨组重复与自配对排除；数值不同模板和无关题的区分；历史重叠、跨候选重叠、标签替换和题干哈希篡改的拒绝。测试未使用 MLX 或 GPU。

该清单仍是**预留确认候选**。开发规则冻结、源题/解释/变式审核及所有相应质量门槛通过后才能做一次性确认；本报告不意味着确认已执行。不能依据确认效果反复替换候选；若某源题质量不合格，记录原定名额、有效数和拒绝原因，并预声明统一处理。最终回收进入全量训练后，P60/H200 不能再作为独立最终测试集。

首报告不可覆盖。再次核查时保留现有规则、报告与输入快照，在代码中显式建立新版本路径，不重跑 `prepare.py` 改写原有冻结数据。正式训练和公开测试门槛仍关闭。
